nsqlookupd is retaining old topics and channels, even after the corresponding nsqd has gone away. This also applies to normal-named channels within an ephemeral topic. The same issue arises when an nsqd unregisters an entire topic. Durable topics/channels should behave as they currently do, but ephemeral topics/channels should only be kept while some nsqd is referencing them. We should consider an nsqd dead (and thus remove its topics/channels) after it has failed to send a ping in a period of time greater than --inactive-producer-timeout, while nodes that continue to ping should remain registered.

There is a use of `*` as a topic name that caused an nsqlookupd to delete all topics, which can be reproduced with a `POST /topic/delete?topic=*`. As `*` is not a valid topic name, /lookup, /channels, /topic/delete and /topic/tombstone should return 400. Tombstone also fails when an IPv6 address is written as nsqadmin displays them, such as [fd00::7]:4151.

Malformed message sizes will cause both services to fail. An IDENTIFY request with a negative body size causes nsqlookupd to crash, while a very large value will cause it to freeze. Values of zero, negative numbers, and sizes over 1MB should return E_BAD_BODY and kill that connection, without affecting other clients. If an nsqd receives a negative size in a response from lookupd, it should kill that connection and continue running.
