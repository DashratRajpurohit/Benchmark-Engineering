no-local option being applied for a shared subscription should probably return DISCONNECT 0x82, while the no-local option currently works for normal subs. Sending DISCONNECT with 0x04 should result in the will message being sent as opposed to a DISCONNECT as normal. Wildcards can only be used on their own as a topic level, so +a, a+, a/+b and a# topics are all rejected for 3.1.1 and 5 while other topics that are valid subscription filters are accepted. An MQTT 5 client should receive DISCONNECT 0x8E if the session is taken over, and connecting an MQTT 3.1.1 client with a blank id should return CONNACK 0x02 if allow_zero_length_clientid is false.

Expired sessions should be removed from the client list at a rate of session_expiry_check_interval. Subscriptions held for each session should be removed if the client is removed, for example for a clean disconnect, or due to session expiring, but should still be shown if the client is connected. Retained message with a payload or empty payload should be settable and unsettable via a topic alias with an empty topic. Publishing with retained: true via the HTTP publish message for admin should result in the message being stored for future subscribers, unsettable with empty payload and retained, and shouldn't store if no retained is specified.

We shouldn't specify Maximum QoS in CONNACK if set to 2, and should otherwise reflect the maximum_qos setting. SUBACK granted QoS shouldn't be greater than maximum_qos across all versions, and sending a PUBLISH with a QoS greater than maximum_qos should return DISCONNECT 0x9B for v5 and close connection for 3.1.1. Published and retained messages should have the remaining expiry time once waited for if included originally in Message Expiry, and not otherwise, which applies to forwarded messages too, and retained messages that have expired shouldn't be sent while ones that have no expiry and are retained should. Sending a message on any topic alias up to the Topic Alias Maximum should succeed, even if topic_alias_maximum is greater than server_receive_maximum.
