Give CDC a way to hold specific columns back, per table, from the row payloads it delivers to its webhook.

The mechanism is a per-table denylist: an operator lists, for each table that needs it, the column names whose values must never show up in that table's emitted "before" or "after" data. Tables left out of the list behave exactly as they do today, and naming a column that doesn't exist on the table is not an error -- it's simply ignored. Where a column is excluded, its value disappears from both row images and for every operation kind (insert, update, delete alike); the column-name list and the row-value list on each event must still describe the same positions. This has to sit alongside the existing table-level filter and row-IDs-only mode without either disturbing the other. Checked eagerly at config load: an entry naming an empty table or an empty column is invalid and must fail with an error.

Three events can leave the column list stale, and each has to force a refresh: a DDL statement against a filtered table (adding, dropping, or renaming a column); a full restore that swaps in a different database, possibly with a different schema; and a change of which cluster node is driving CDC after a Raft leadership handoff.

Whichever triggers it, every event produced afterward must be built from the columns and filtering as they stand right now -- nothing carried forward from before the change. One wrinkle: when a single explicit transaction both writes a row and runs column DDL, build the event from that transaction's final columns regardless of statement order. Values travel with their column's identity rather than its name, so a rename keeps its already-written value, while a column dropped and re-added under the old name counts as a new column, not a continuation -- wherever identity can't be traced to a write, report NULL. One more path: if the schema-version read guarding the cached filtering metadata returns a transient error, treat it exactly like a detected change -- discard the cache, rebuild it, and still deliver the event rather than serving stale data or dropping it.

Concrete production surface: a new top-level JSON key in the CDC config, "column_filter", mapping table names to excluded columns (absent means unfiltered), exposed on the parsed config as ColumnFilter map[string][]string. db.NewCDCStreamer takes a third parameter of that type. store.Store.EnableCDC gains one more trailing parameter of the same type, after its table-filter and row-IDs-only arguments. db.ColumnsNameProvider gains a second method, SchemaVersion() (int64, error), changing whenever the table's schema does. db.CDCStreamer gains an exported InvalidateAll() method that discards its cached column-name and filter state so the next commit rebuilds it fresh.
