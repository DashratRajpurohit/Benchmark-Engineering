If a Set() call is made with a key that is already present, ShouldUpdate is used to determine whether to use the new value. If the item is rejected, then the original value should remain in the cache and OnReject and OnExit should not be called. RemainingCost should still reflect the value being kept.

If multiple Set() calls happen with the same key, then ShouldUpdate determines which value will be kept, RemainingCost should reflect the Cost() of that value, OnReject should not be called, and OnExit will be called when that item is removed or overwritten. A Set() call to an item should be treated as an update if a previous Set() call to the same item hasn't been applied yet. Updates to an item that is already in the cache should not be dropped, even if the write buffer is full. A Set() call to an item should not cause ShouldUpdate, OnReject or OnExit to be called with the values of other items that have the same primary hash but a different conflict hash. Set() and Del() calls to the same item will be applied in the order they were called, regardless of any other pending operations.

If a Del() call is made with a key that is not present, then no notification should take place. Otherwise, OnExit should be called exactly once with the value. When there is also a pending Set(), there should still only be one notification. If there is also an eviction, expiration, or a call to Clear(), then there should be one notification for the item and it should never be notified with a zero value.

OnExit() is allowed to free the value it receives, meaning that the value cannot be inspected again, so it should not be passed to ShouldUpdate or Cost() once OnExit has been called with it. OnEvict should be called with a separate Item for each evicted entry, providing its value, Expiration, and the cost that was accounted for in RemainingCost when it was evicted.
