TiDB does not have the MySQL XML functions ExtractValue(xml_frag, xpath_expr) and UpdateXML(xml_target, xpath_expr, new_xml), so calling either one fails because the function does not exist. Please add both so they work the way the MySQL 8.4 manual describes them.

ExtractValue should return the text of every element the XPath expression matches. Only the element's own text is returned, not the text of its children, and several matches are joined with one space in document order. CDATA counts as text, text is returned exactly as written, and matching an attribute returns its value. An empty element or a path that matches nothing gives an empty string. The XML may have several top level elements, and comments and the XML declaration are skipped.

XPath support should cover absolute and relative paths (relative paths start at the root), //, *, unions with |, prefixed names such as e:f, predicates using positions, last(), position(), attribute tests, and, or, not() and paths like ../@c, and the child, descendant, descendant-or-self, parent, ancestor, ancestor-or-self, self and attribute axes. Expressions that do not return nodes should work too: count(), sum(), the arithmetic operators, comparisons and boolean functions (returned as 1 or 0), number(), floor(), ceiling(), concat(), substring(), string-length() and contains(). A node set in a comparison is true if any of its nodes matches. String comparisons and contains() use the collation of the arguments, combined the same way CONCAT() combines them.

$@name in an XPath expression reads the user variable @name, whose name is not case sensitive, each time the statement runs, including when a prepared statement is executed again. An unset variable matches nothing.

If any argument is NULL the result is NULL. Malformed XML gives NULL with warning 1525 Incorrect XML value. An invalid XPath expression, or one that uses a function MySQL does not support such as name() or starts-with(), fails the statement with error 1105 XPATH syntax error and changes nothing.

UpdateXML replaces the matched part with new_xml only when exactly one node matches, otherwise the original value is returned unchanged. The rest of the XML is kept exactly as written and new_xml is not validated. Both functions should work on table columns, and ExtractValue should be allowed in generated columns while UpdateXML stays disallowed there.
