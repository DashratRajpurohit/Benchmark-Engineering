Fix zoekt-index and zoekt-git-index so indexing more than one input under one repository name in a single invocation never silently loses data.

Every input in one invocation must end up searchable under its intended name. Each positional argument is its own input, including when the same path is listed more than once. Any partial failure among inputs sharing a name must leave nothing new published under that name: whatever previously existed there from an earlier successful run stays completely untouched, and other, unrelated names in the same invocation still finish. Two merged inputs that would each write a file at the same relative path must be treated as an explicit conflict for that name, and a `-delta` build must never merge more than one input under a shared name.
