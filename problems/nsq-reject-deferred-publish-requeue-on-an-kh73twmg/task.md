- A publish or a requeue should fail once its channel has begun exiting. This already happens for a normal publish and an immediate requeue, but not for a deferred publish or a requeue carrying a timeout, so messages can be accepted during shutdown. Such messages shouldn't get written to the backend or delivered to a consumer, and the caller should get an appropriate error. The same applies to anything else that re-registers a message that's already in flight.
- If the topic doesn't have a channel, and the topic is exiting, don't create the channel. The request should fail, otherwise we'll end up with a channel with no topic. It should fail right away too, not wait around for the topic to finish exiting. This applies to explicit attempts to create the channel as well.
- If the topic or channel has begun closing, subscribers should be treated as though they're subscribing after the deletion is complete, meaning they should be placed on a new topic/channel as applicable. However, if deletion fails and the channel is still around, a subscriber that tries to connect during or after that deletion should get an error instead of hanging around forever.
- If deletion is in progress, attempting to delete it again should have no effect on the outcome of the first deletion.
- Ephemeral topics and channels get deleted on their own once the last channel or consumer goes away. Only delete it if it's still unused when that actually happens. If someone subscribed or a channel got created on it in the meantime, leave it alone.
- Also, if a consumer takes a message right as its channel is closing (not as part of deletion), that message shouldn't get lost - the close should still end up delivering or writing it out.
